About activity approvals

Activity approvals let your organization require formal sign-off on an activity before it moves forward. An approval covers the whole activity, including its details, budget, Impact, and KPIs.

Activity approvals are in Preview, and are not enabled in your Uptempo instance by default. Contact your Customer Success Manager to enable this feature.

How activity approvals work

Activity approvals involve three roles:

Admin

Creates approval processes, decides which activity types need approval and who approves them, sets the default approver, and sets how approval emails are sent.

Submitter

Submits an activity for approval and sets a deadline for the decision.

Approver

Reviews requests and approves or denies them, either on the Approvals page or from the activity's details panel on the Timeline.

A typical approval follows these steps:

  1. An admin creates an approval process that covers one or more activity types, with one or more approval steps.

  2. A submitter opens an activity of a covered type, selects Submit for Approval, reviews the approval route, and sets a deadline. Uptempo creates an approval request with the status Pending review, and emails the approvers for the first step.

  3. Any one of the approvers for the current step approves or denies the request, on the Approvals page or from the activity's details panel on the Timeline.

  4. If there's another step, the request moves to it, and its approvers are emailed. This repeats until the final step is approved.

  5. The request moves to Approved after the final step is approved, or to Denied as soon as any step is denied. Each decision is recorded in the request's approval history.

Approval processes

An approval process defines which activity types need approval, and who approves them. Each process has:

  • A name, an optional description, and a status (active or inactive).

  • One or more activity types that it covers. One process can cover several activity types, but each activity type belongs to only one active process.

  • One to five approval steps. Each step has an optional name, such as Manager or Director, and an approver source: submitter, activity owner, or selected by submitter.

Only activities whose type is covered by an active process can be submitted for approval. Activities of other types don't show Submit for Approval, and don't appear on the Approvals page.

Approval steps

A request moves through a process's approval steps in order:

  • One step at a time: Approvers for a step see the request only after the step before it is approved.

  • Any one approver decides a step: When a step has several approvers, the first one to approve or deny settles that step. The other approvers on the step see that it's been decided, and by whom.

  • Every step is decided: No step is skipped. If a step has no eligible approver, it goes to the default approver.

  • The same person can act at several steps: If someone is an approver on more than one step, they decide at each step the request reaches.

  • One deadline covers the whole route: The submitter sets one deadline for the request. Overdue and approaching status apply to whichever step is current.

How approvers are assigned

Each approval step uses one of three approver sources:

Submitter

An admin uploads a submitter-to-approver mapping for the step: a file that maps each submitter to one or more approvers. Uptempo assigns all approvers on the submitter's row. The submitter can't change them.

Activity owner

An admin uploads an activity owner-to-approver mapping for the step: a file that maps each activity owner to one or more approvers. Uptempo assigns all approvers on the activity owner's row, whoever submits the request. The activity owner is the user in the activity's Owner field. This source is available only when every activity type in the process has the Owner field turned on.

Selected by submitter

The submitter chooses one approver for the step when submitting. Only users who can edit the activity can be selected. If the approver they need isn't listed, submitters see a message that explains what to do next. Admins can customize this message.

Uptempo records the activity owner when the request is submitted. If the activity owner changes afterward, the request stays with its original approvers. The new activity owner applies from the next request.

Default approver

The default approver is the person who receives a step when it has no eligible approver. An admin sets one default approver for all activity approval processes.

Uptempo sends a step to the default approver when:

  • The submitter, or the activity owner, isn't listed in the step's mapping file.

  • The only approver for the step is the submitter (when using the submitter-to-approver mapping) because submitters can't approve their own requests unless they are administrators.

  • None of the step's approvers can edit the activity, including approvers who lose edit access while the request waits at their step.

Submission is never blocked in these cases. The step is marked as reassigned, and the approval history records the reason.

Approval routes are fixed when a request is submitted. Changes to a process, its approval steps, or its mapping files apply to new requests only. Requests in progress finish on their original route.

Request statuses

Every request has one of the following statuses:

Pending review

The request has been submitted and is waiting for a decision at one of its steps.

Approved

Every step of the request was approved. Approval is final: once an activity has an approved request, it can't be submitted for approval again.

Denied

An approver denied the request at one of its steps. Later steps aren't started. The request stays denied, and the activity can be submitted for approval again.

An activity can have only one pending request at a time, and only one approved request. When a request is denied, the submitter can update the activity and submit a new request. The new request starts at the first step, and approvals from the denied request don't carry over. The denied request stays on the Approvals page, so an activity can have several denied requests.

Admin decisions

An admin can approve or deny any pending request at its current step, even if they aren't one of the step's approvers. An admin's decision counts for the current step only. Later steps still need their own approvers, and the approval history records the decision as an admin decision.

What an approval covers

An approval covers the activity as it stands when the decision is made. Activity fields aren't locked while a request is pending, so the activity can still be edited during review.

Who can see and decide on requests

  • To see a request, you need view access to the activity. You can see requests for every activity you can view, including requests that aren't assigned to you. You can also see the activity owner and the full approval route, including the status of each step.

  • To approve or deny a request, you must be an approver for its current step, the default approver for a reassigned step, or an admin.

Approval history

Each request's approval history records every event, with who and when: the submission, the activity owner at submission, each step's approval or denial with its comment, and each reassignment to the default approver with its reason. Approval processes, mapping file uploads, and changes to approval steps and the default approver are recorded in the audit trail.

Approval emails

Uptempo emails approvers when a request reaches their step. Admins choose whether approvers get an email as soon as each request reaches them, a daily or weekly digest, or both.

Submitters get an email when their request is approved or denied.
